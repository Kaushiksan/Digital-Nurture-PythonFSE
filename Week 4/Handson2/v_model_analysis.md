# Task 1: SDLC vs STLC

## Software Development Life Cycle (SDLC)

SDLC is the complete process of developing software from planning to maintenance.

### Phases
1. Requirement Analysis
2. Planning
3. Design
4. Development
5. Testing
6. Deployment
7. Maintenance

---

## Software Testing Life Cycle (STLC)

STLC is the testing process followed to ensure software quality.

### Phases
1. Requirement Analysis
2. Test Planning
3. Test Case Development
4. Environment Setup
5. Test Execution
6. Defect Reporting
7. Test Closure

---

## SDLC vs STLC

| SDLC | STLC |
|------|------|
| Develops the software | Tests the software |
| Covers the complete project | Covers only testing activities |
| Performed by developers and stakeholders | Performed mainly by QA engineers |
| Goal is software development | Goal is software quality |

# Task 2: V-Model

## What is the V-Model?

The V-Model is a software development model where every development phase has a corresponding testing phase.

```
Requirement Analysis  <----> Acceptance Testing

System Design         <----> System Testing

Architecture Design   <----> Integration Testing

Module Design         <----> Unit Testing

            Coding
```

### Advantages

- Early test planning
- Better defect detection
- Improved software quality
- Easy traceability
- Suitable for stable requirements

### Limitations

- Difficult to accommodate changing requirements
- Less flexible than Agile
- Higher cost if requirements change late

# Task 3: Agile QA

## Agile Testing

Agile testing is continuous testing performed throughout development rather than only at the end.

### Principles

- Continuous testing
- Customer collaboration
- Fast feedback
- Automation wherever possible
- Frequent releases

### Benefits

- Faster defect detection
- Better product quality
- Reduced development cost
- Faster delivery
- Improved customer satisfaction

---

# Task 4: Shift-Left Testing

Shift-Left Testing means testing activities begin as early as possible during software development.

### Benefits

- Detects defects early
- Reduces fixing cost
- Improves code quality
- Saves testing time
- Improves collaboration between developers and testers

---

# Task 5: Scenario Analysis

## Scenario

A banking application receives frequent requirement changes.

### Recommended Model

**Agile Model**

### Reason

- Supports frequent requirement changes
- Short development iterations
- Continuous customer feedback
- Continuous testing
- Faster release cycles

The V-Model is more suitable when requirements are stable, whereas Agile is better for projects with changing business needs.
